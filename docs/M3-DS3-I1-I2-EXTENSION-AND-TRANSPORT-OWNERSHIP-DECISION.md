## I1 — candidate A: internal modules are not an advertised HID plugin ABI

1. **PROVEN (source):** [`btif/src/bluetooth.cc:416-464`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/btif/src/bluetooth.cc#L416-L464) selects precompiled profiles; `BT_PROFILE_HIDHOST_ID` calls `btif_hh_get_interface()`. It exposes no third-party HID callback registrar at this callsite.
2. **PROVEN:** [`btif/src/btif_hh.cc:1222-1234`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/btif/src/btif_hh.cc#L1222-L1234) stores one `bthh_callbacks_t*` and enables the internal HID service; [JNI `com_android_bluetooth_hid_host.cpp:181-236`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/packages/apps/Bluetooth/jni/com_android_bluetooth_hid_host.cpp#L181-L236) supplies its known callback table. This is an existing privileged service-to-native registration, **not** a public registration for a separate .so.
3. **PROVEN, important false-positive:** [`btcore/src/module.cc:56-60`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/btcore/src/module.cc#L56-L60) resolves a `module_t` via `dlsym(RTLD_DEFAULT,name)`; [`btif/src/stack_manager.cc:144-193`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/btif/src/stack_manager.cc#L144-L193) either uses a **compiled module lookup table** (`STATIC_LIBBLUETOOTH`) or calls `get_module(name)` for the stack's named modules. Neither path loads arbitrary plugins or registers a DS3 HID/security/L2CAP handler. Merely linking a new library does not make the stack request its symbol.
4. **PROVEN, second false-positive:** [`main/Android.bp:150-155`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/main/Android.bp#L150-L155) mentions `dlopen` to explain **test** link options (`-Bsymbolic`), not runtime HID extensibility.
5. **PROVEN:** [`stack/hid/hidh_conn.cc:70-81,95-116`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/stack/hid/hidh_conn.cc#L70-L116) wires static HID L2CAP callbacks and registers both HID PSMs. [`gd/hal/hci_hal_android_hidl.cc:208-240`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/gd/hal/hci_hal_android_hidl.cc#L208-L240) obtains and initializes an Android Bluetooth **HCI transport HAL**; this is not an external Classic HID Host plugin service.

**I1 decision: A = NO_GO for a supported drop-in .so extension on the inspected public H618 architecture.** No actual versioned extension/loading/callback ABI was found in the enumerated interfaces. This is not a claim that every OEM-proprietary source file has been exhaustively searched. OEM-specific published addon ABI with concrete load path, callback signature, security/PSM routing and lifecycle would reopen A. **Do not substitute ptrace, inline hooking, linker namespace tricks or `dlopen` injection.**

## I2 — candidate B: managed BR/EDR sockets are real; DS3 HID ownership is not delegated

### Positive capability that needs careful qualification

- **PROVEN (source):** Android has an internal BR/EDR `BTSOCK_L2CAP` path, separate from LE CoC: [`btif/src/btif_sock.cc:130-171,191-230`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/btif/src/btif_sock.cc#L130-L230). [`btif_sock_l2cap.cc:729-799`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/btif/src/btif_sock_l2cap.cc#L729-L799) routes Classic client/server requests to BTA JV via `BTA_JvL2capConnect/StartServer` and returns a socket FD over Android's existing Bluetooth stack.
- **PROVEN:** [`frameworks/base/.../BluetoothDevice.java:2212-2267`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/frameworks/base/core/java/android/bluetooth/BluetoothDevice.java#L2212-L2267) contains hidden `createL2capSocket(int)` and `createInsecureL2capSocket(int)` (BR/EDR). [`BluetoothAdapter.java:2883-2972`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/frameworks/base/core/java/android/bluetooth/BluetoothAdapter.java#L2883-L2972) has hidden Classic `listenUsingL2capOn` variants. These are **not publicly supported third-party DS3 extension APIs**; platform compatibility, hidden-API restrictions, permissions and M3 availability remain **UNTESTED**.
- **PROVEN:** The publicly exposed Android `createL2capChannel(int)` in [`BluetoothDevice.java:2578-2611`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/frameworks/base/core/java/android/bluetooth/BluetoothDevice.java#L2578-L2611) uses `TYPE_L2CAP_LE`. **Do not mistake it for Classic HID PSM access.**

### Actual conflict and corruption hazard

1. **PROVEN:** [`stack/hid/hidh_conn.cc:95-116`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/stack/hid/hidh_conn.cc#L95-L116) registers Classic PSMs **0x11** and **0x13** with `BTA_SEC_AUTHENTICATE | BTA_SEC_ENCRYPT`; [lines 171-244](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/stack/hid/hidh_conn.cc#L171-L244) treat incoming DS3-like control then interrupt as the owned HID Host state machine.
2. **PROVEN:** [`bta/jv/bta_jv_act.cc:506-550`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/bta/jv/bta_jv_act.cc#L506-L550) `bta_jv_check_psm` specially gates HIDC/HIDI using `!bta_sys_is_register(BTA_ID_HD) || !bta_sys_is_register(BTA_ID_HH)`. **Nuance:** the OR means the check can return true when one of these services is absent. It is **not** evidence that the PSM is available, exclusive or safely shareable. [Outgoing JV: 913-925](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/bta/jv/bta_jv_act.cc#L913-L925) and [incoming JV: 1057-1065](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/bta/jv/bta_jv_act.cc#L1057-L1065) both apply this check to Classic PSMs.
3. **PROVEN / CRITICAL:** [`stack/l2cap/l2c_api.cc:112-145`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/stack/l2cap/l2c_api.cc#L112-L145) creates a **virtual PSM only for outgoing-only DYNAMIC PSM >=0x1001**. For fixed HID PSM 0x11/0x13, an existing RCB is found and explicitly **overwritten** (`p_rcb->api = p_cb_info`). This is not a multi-listener broker. [`stack/gap/gap_conn.cc:220-247`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/stack/gap/gap_conn.cc#L220-L247) calls `L2CA_Register2(psm,...)` for both Classic client and server. Thus even an apparently successful hidden socket open on a fixed HID PSM may **replace the OEM registered callback ownership**. A test simply checking whether `connect()/listen()` returned success is a **dangerously invalid coexistence test**.
4. **PROVEN / RISK:** [`L2CA_Register2:51-58`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/stack/l2cap/l2c_api.cc#L51-L58) separately calls `BTM_SetSecurityLevel`. A competing registration must not be assumed security-neutral. [`L2CA_Deregister:158-195`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/stack/l2cap/l2c_api.cc#L158-L195) operates by PSM and disconnects associated channels, not an independent owner-tagged registration. Cleanup of an unauthorized second listener could disrupt the first.
5. **PROVEN:** The existing [HCI layer](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/hci/src/hci_layer.cc#L199-L305) controls startup/stop of the HAL transport; [GD Android HIDL HAL](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/system/bt/gd/hal/hci_hal_android_hidl.cc#L208-L240) initializes the service and owns event callbacks. **INFERRED:** two simultaneous independent HCI schedulers without arbitration are unsafe; root or a kernel AF_BLUETOOTH socket does not create HCI multiplexing. Current M3 lacks a demonstrated usable Linux HCI controller.

**I2 decision:** B using the **same M3 controller** and the exact HID PSMs is **NO_GO as an independently coexisting daemon on current evidence**. Managed Bluetooth sockets are a real general capability, but **not** delegated HID-host traffic. Hidden Classic methods may only be useful for separate, non-conflicting PSMs, not this DS3 problem. Same-controller B could reopen only on an OEM-proven **per-peer, callback-safe PSM broker** that preserves HID ownership and native security; none identified. It cannot solve historical 0x22 by creating UHID.

**Alternative B2 — independent USB Bluetooth adapter:** **CONDITIONAL / UNTESTED**, *only* if M3 kernel/drivers expose a separately usable USB HCI transport to a second process without interfering with OEM UART Bluetooth; BlueZ/own stack could then exclusively own that **different physical controller**. Requires read-only host driver/kernel/OTG assessment and a removable hardware design, not a claim of readiness. One-time DS3 USB enrollment would need to target the selected dongle host address. No dongle was tested.

## I4 — candidate D: existing privileged settings cannot repair unbonded authentication

- **PROVEN:** [`HidHostService.java:892-917`](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/packages/apps/Bluetooth/src/com/android/bluetooth/hid/HidHostService.java#L892-L917) refuses a peer unless `BOND_BONDED` and connection policy acceptable; [lines 601-619](https://github.com/BPI-SINOVOIP/BPI-H618-Android12/blob/250eabfc529518b7f26432663ed0a867ab2f625d/packages/apps/Bluetooth/src/com/android/bluetooth/hid/HidHostService.java#L601-L619) set connection policy, **not** HCI authentication or PIN semantics. `BluetoothHidHost` privileged methods are existing-client controls, not HCI or HID L2CAP callback delegation.
- **PROVEN / already recorded:** USB `sixpair` changes the controller's host address; it does not itself make Android issue or persist a Classic LinkKey. The previously observed HCI 0x22 occurs **upstream** of the Java bond gate and UHID SET_REPORT handling.
- **D decision: NO_GO for any identified stock configuration/API solving the observed unbonded DS3 path.** Hidden/privileged commands are not proof of an owner-scoped secure exception. New OEM-specific API remains **UNTESTED** until documented.

## I6 — architecture comparison and strictly scoped next action

| Design | GO gate | Decision (2026-11-02) | Maintainability / risk |
| --- | --- | --- | --- |
| **A. OEM in-process extension .so** | Published/verified load + versioned HID/auth/L2CAP callback ABI, uninstallable without injection | **NO_GO**; inspected selectors/modules are internal | Would be best if it existed; arbitrary injection prohibited |
| **B. Standalone same-controller daemon** | Delegate inbound 0x11/0x13 **without changing OEM RCB**, with trusted authenticated peer and HCI arbitration | **NO_GO** for direct fixed-PSM registration / dual HCI | RCB overwrite + security/cleanup + 0x22; no safe same-controller PoC yet |
| **B2. Standalone with separate USB HCI dongle** | Verified separate kernel HCI device, transport, power/boot persistence and physical recovery | **CONDITIONAL / UNTESTED** | Removable, but requires extra hardware, drivers and own Bluetooth stack |
| **D. Stock Android/OEM API** | Existing supported per-device sixpair-compatible auth / HID delegated transport | **NO_GO** on inspected methods | Hidden Classic sockets and policy setters do not satisfy it |
| **C. Minimal source-level bridge** | Explicit Owner decision to modify Fluoride; verified native and Java gates + target ABI/build | **FALLBACK ONLY / CONDITIONAL** | Complicated integration; closest to PR #51; no automatic BSP acquisition |

### Smallest legitimate reversible PoC — **offline first, no radio traffic**

1. **Now (no device permission needed):** execute a pinned-source static **ownership gate** that verifies the specific `module`, `get_profile_interface`, `bta_jv_check_psm`, `GAP_ConnOpen`, fixed-PSM `L2CA_Register` overwrite and Java BOND_BONDED callsites. Fail closed on source drift and never equate a socket success to controller access. No UHID implementation yet.
2. **Only after separate Owner approval:** *read-only* M3 inventory of second USB HCI/USB host driver availability, verified OEM socket provider/version/privilege evidence and normal Bluetooth state. Avoid opening fixed HID sockets, capturing secrets or triggering pairing. Approval must describe commands and output redaction.
3. **Only if B2 hardware prerequisites pass:** separately approve a bounded one-shot test using a **dedicated** controller with no OEM PSM overlap; confirm transport and genuine DS3 on-air authentication **before** a UHID bridge. No reboot hooks, daemon autostart or permanent settings during feasibility.
4. **If B2 fails and no documented OEM broker exists:** present A/B/D NO_GO to Owner, and **ask** whether C / PR #51 is acceptable. Do not silently migrate this PR to source patching.

### Non-negotiable falsification rules

- Do not infer a supported plugin from `dlsym`, Bluetooth's HAL profiles, Java callbacks, or an `Android.bp` dependency.
- Do not call a native Binder/hidden Classic socket successful merely because the Java object was created. Most importantly, **do not** try 0x11/0x13 listening/connecting while the OEM HID Host runs: a result may clobber its callback table.
- Do not use root, Linux `AF_BLUETOOTH`, a `socketpair(AF_LOCAL)`, or `hci0` assumptions to claim ownership of the OEM UART/HIDL HAL.
- No spoofable MAC-only trust, fabricated LinkKeys/BOND_BONDED, insecure global HID masks, system writes, firmware flashes, SELinux/AVB bypass, service restart or injection.
- Keep M3 and its configuration untouched until explicit, separately scoped Owner approval. PR #52 stays Draft.
